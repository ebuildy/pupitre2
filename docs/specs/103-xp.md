# 103 — Experience points (XP), levels and leaderboard

| Field | Value |
| --- | --- |
| Area | Gamification |
| Actors | learner, admin, anyone (leaderboard) |
| Related | [040](040-courses-and-catalogue.md), [045](045-course-page-and-enrollment.md), [165](165-admin-courses.md) |

Covers the original 103 (awarding), 104 (levels), 105 ("Mon XP"), 049 (XP-gated enrollment), the course-completion
record of 068/191 (marked by an admin for now), and an XP leaderboard.

## XP events

Table `xp_event`: one row per gain or correction. **Total XP = sum of `amount`.**

| Source | `sourceKey` | Amount | Status |
| --- | --- | --- | --- |
| `lesson` | module id | 10 (`XP_AMOUNTS.lesson`) | lesson completed ([053](053-course-content-and-quizzes.md)) |
| `quiz` | module id | 25 (`XP_AMOUNTS.quiz`) | quiz passed for the first time ([053](053-course-content-and-quizzes.md)) |
| `course` | course id | the course's `completionXp` (default 200) | course completion (below) |
| `admin` | random id | any non-zero integer, with a reason | admin adjustment |

- At most one event per (user, source, sourceKey) (unique index + insert-or-ignore, `awardXp()`): repeating an action never pays twice.
- Each event keeps a `label` (course title, or the admin's reason) and an optional `courseId` (set to null if the course is deleted): earned XP survives the course.
- An admin adjustment is refused when it would make the total negative (400 `XP total cannot become negative`).

## Course completion

Table `course_completion`: at most one per (user, course), with its date and a snapshot of the course title (kept if the
course is deleted).

- Completing the last module completes the course automatically ([053](053-course-content-and-quizzes.md)). An admin can also mark a course completed for an **enrolled** learner (400 `User is not enrolled in this course` otherwise). The completion and the `course` XP event are written together (one transaction); completing again changes nothing.
- An admin can undo a completion: the record and its XP event are removed.

## XP-gated enrollment (spec 049)

- Courses have `xpRequired` (≥ 0, default 0) and `completionXp` (≥ 0, default 200), set in the admin course form.
- `POST /api/enrollments/:slug` with less XP than `xpRequired` → 403 `Not enough XP to enroll in this course`. Admin enrollment ignores the gate.
- Catalogue cards show "⚡ N XP requis" and "+N XP"; the course page shows "⚡ N XP requis pour s’inscrire" and, when signed in without enough XP, "Il vous manque M XP (vous en avez K)." with the enroll button disabled.

## API

| Endpoint | Result |
| --- | --- |
| `GET /api/my/xp` (session) | `{ total, history: [{source, amount, label, course: {slug,title}|null, earnedAt}], inProgress: [{slug, title, completionXp}] }`, history most recent first; `inProgress` = enrolled, published, not completed |
| `GET /api/leaderboard` (public) | `{ leaderboard: [{rank, username, name, image, xp}], me: {rank, xp} | null }`: active non-admin users with XP > 0, top 20, ties share a rank (1, 1, 3); `me` is the viewer's own position |
| `POST /api/admin/courses/:id/completions {userId}` | mark completed → `{message: "Course completed"}` |
| `DELETE /api/admin/courses/:id/completions/:userId` | undo → `{message: "Completion removed"}` |
| `GET /api/admin/users?search=` | `{users: [{id, username, name, email, role, isActive, xp}], total}` (200 max) |
| `GET /api/admin/users/:id` | the user + `xp`, `history`, `completions` |
| `POST /api/admin/users/:id/xp {amount, reason}` | adjustment → `{total}` |

`CourseSummary` gains `xpRequired`, `completionXp`, `completed`; `CourseDetail` gains `completedAt`, `userXp`;
"Mes cours" items gain `completedAt`; admin enrollments gain `completedAt`.

## UI

- Top bar: "Mon XP" (signed in), "Classement" (everyone).
- `/my-xp` ("Mon XP"): "N points accumulés"; big total "points d'expérience" with the level badge; progress bar
  "X XP jusqu’au niveau L (Nom)" or "Niveau maximum atteint 🏆"; level ladder (5 cards, current highlighted, "Départ"
  for 0); "En cours (N cours)" with "Compléter pour +N XP"; history (icon and source label — Leçon terminée, Quiz réussi,
  Cours terminé, Ajustement —, course link or reason, date, "+N XP" / "−N XP"); empty: "Aucun XP gagné pour l'instant…".
- `/leaderboard` ("Classement"): "Votre position : #N (X XP)" or "Gagnez de l’XP pour apparaître dans le classement.";
  🥇🥈🥉 for ranks 1–3, then "#N"; avatar initial, username, level badge, XP; the viewer's row is highlighted.
- Course card: "✓ Terminé" replaces "✓ Inscrit" once completed. Course page: "✓ Cours terminé le …" and an
  "⚡ XP de ce cours" card ("+N XP à l’achèvement" / "+N XP obtenus ✓", links to `/my-xp`). "Mes cours": "✓ Terminé le …".
- Admin: course form fields "XP requis pour s’inscrire" (0 = aucune condition) and "XP à l’achèvement"; enrollment
  list column "Achèvement" with "Marquer comme terminé" / "✓ Terminé le … · Annuler l’achèvement"; "Utilisateurs"
  page (search, role, level, XP) and user page (total + level, adjustment form "Montant (négatif pour retirer)" +
  "Motif" → "XP mis à jour : N XP au total", completed courses, XP history).

## Acceptance criteria

- Completing a course grants its completion XP once; undoing removes it; deleting the course keeps it.
- With less XP than required, self-enrollment is refused (UI and API); after an XP adjustment it works.
- The leaderboard orders learners by XP, leaves out admins and deactivated users, and shows the viewer's position.
- An admin adjustment needs a non-zero integer and a reason, and can't make the total negative.

## Differences from the original

- Admins can also mark a completion by hand (and undo it).
- Admin adjustments (target model) and per-course completion XP replace the fixed 200 XP.
- The leaderboard ranks XP; the original public leaderboard ranked badges (108), which don't exist yet.
- Not yet: badges (106), skill levels on completion (113), XP on cards' progress.
